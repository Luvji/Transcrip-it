# Meeting management

The Rust backend is the source of truth for the local meeting library. The desktop frontend uses Tauri commands to create and list meetings, rename them, replace their tags, archive and reopen them, and permanently delete them.

## Identity and retries

Meeting IDs are generated by the caller and remain stable. Creation, archive, and reopen operations carry unique idempotency keys so a UI retry cannot create a duplicate record or repeat a lifecycle transition. Reusing a key for different input is rejected.

## Archive and deletion

Archiving is reversible and preserves the lifecycle state that preceded it. Only draft, ready, and failed meetings can be archived; an active recording or processing job must be stopped first. Reopening restores the saved state. Permanent deletion removes the meeting and all records owned by it through foreign-key cascades.

Tags are trimmed, deduplicated case-insensitively, sorted for stable display, and replaced transactionally. Meeting titles must contain at least one non-whitespace character.

## Desktop command surface

- `create_meeting`
- `list_meetings`
- `rename_meeting`
- `replace_meeting_tags`
- `archive_meeting`
- `reopen_meeting`
- `delete_meeting`

All data stays in the local SQLite database described in [`persistence.md`](persistence.md).
